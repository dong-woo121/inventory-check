# 재고확인

HTML/CSS/Vanilla JS 기반의 정적 웹앱입니다. 주문 원본을 브라우저에서만 처리하며 별도의 서버나 DB가 필요하지 않습니다.

## GitHub Pages 배포하기 (최초 1회)

1. GitHub에서 **새 공개(Public) 저장소**를 생성합니다. 예: `inventory-check`.
2. 이 폴더 안의 `index.html`, `style.css`, `script.js`, `.nojekyll`, `README.md` 파일을 저장소 **최상위(root)** 에 업로드합니다. `inventory-check/`라는 하위 폴더 안에 넣지 마세요.
3. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch** 로 이동합니다.
4. **Branch: main**, **Folder: /(root)** 를 선택하고 **Save** 합니다.
5. 배포가 완료되면 `https://<GitHub 사용자명>.github.io/<저장소명>/` 에서 접속합니다. 주소가 실제로 열리기 전에는 배포가 완료된 것이 아닙니다.

이후 기능 변경 시 GitHub 저장소의 같은 파일을 수정/업로드하고 커밋하면 Pages가 다시 배포됩니다. 사용자는 기존 URL에 접속해서 최신 버전을 이용할 수 있습니다. 배포와 브라우저 캐시 반영에는 약간의 지연이 있을 수 있습니다. 화면 상단 버전 표시를 확인하세요.

> **공개 주의:** 공개 저장소 및 GitHub Pages에 배포한 HTML/JS/CSS 코드는 누구나 볼 수 있습니다. 주문 원본이나 공급처 정보, 개인 정보, 비밀키 등을 소스 코드 또는 저장소에 올리지 마세요. 주문 데이터 자체는 브라우저에서만 처리됩니다.

## 기존 로컬 설정 옮기기

GitHub Pages 주소는 기존 `file://` 주소와 저장 공간이 다릅니다. 같은 브라우저라도 설정이 자동으로 옮겨지지 않습니다.

1. 기존 로컬 페이지를 **v1.2.0 파일로 교체한 뒤** 실행합니다.
2. **설정 열기 → 설정 백업(JSON)** 을 눌러 JSON 파일을 저장합니다.
3. GitHub Pages 주소를 열고 **설정 열기 → 설정 가져오기(JSON)** 를 선택해 백업을 복원합니다.
4. 상품 순서·별칭·세트 규칙이 맞는지 확인한 뒤 주문 샘플을 집계합니다.

설정 변경은 **해당 브라우저 localStorage에만** 반영됩니다. 여러 PC/브라우저에서 공유되지 않습니다. 코드 업데이트는 설정을 덮어쓰지 않습니다. 기본 별칭 신규 추가 등 공통 정책을 전원에게 반영하려면 사용자가 보관한 설정과의 병합 정책을 별도로 고려해야 합니다.

## 개발 및 검증

- 오프라인: `index.html` 더블클릭
- 로컬 HTTP: `python -m http.server 8000`, 이후 `http://localhost:8000` 접속
- 테스트: Node.js가 설치되어 있으면 `node test.js`
- 안정성: 미인식 주문 행이 있으면 해당 행 전체를 제외하고 엑셀 복사를 차단합니다.
- 서비스워커 미사용: 브라우저의 장기 오프라인 캐시로 오래된 코드가 남는 위험을 줄였습니다.

## 향후 버전 배포

`index.html`의 `script.js?v=...` / `style.css?v=...` 쿼리 문자열과 화면 상단 버전을 함께 변경하세요. `localStorage`의 `inventory-check-settings-v1` 키는 설정 형식이 호환되는 동안 유지하세요.
